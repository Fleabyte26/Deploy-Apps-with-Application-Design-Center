# CBL558 - Deploy Apps with Application Design Center

This lab is almost all clicks in the App Design Center console. This guide is a checklist with the exact values to type, plus a few Cloud Shell blocks that print your own project and region so you can copy them without typos.

## Known lab traps/bugs (read first)

1. The region is different in every lab instance. Find it in the lab's left panel or in Task 1 of your lab page. Select it at the bottom of the App Design Center left menu BEFORE you click Go to Setup. The wrong region breaks every check.
2. Add the three Cloud Run components in this exact order: data-mcp-server first, agent-backend second, frontend third. Task 4 refers to them by ID (cloud-run-1, cloud-run-2, cloud-run-3). If you delete a component and add it again, it gets a new number and those references point at the wrong service.
3. For Members and for each role, type the value and press Enter so it becomes a chip. Text left in the box without Enter is not saved.
4. Connections have a direction, and the template check does NOT catch a reversed one. Drag from the component named first to the component named second. The arrowhead must end on the second one: frontend -> agent-backend -> data-mcp-server. If the arrows point the other way, the app check in Task 4 fails with a generic message and the deployment cannot work. To fix a reversed line, open the template (Templates > app-template-1), click the line, delete it, and drag it again in the right direction. Connections cannot be changed inside an app. If you already created the app, open it afterwards: a banner says "New template revision available". Click View template revision and update the app to the new revision, then confirm the container values in Task 4 are still there.
5. Two checks are gates. Click "Validate the template configuration" before adding the template to the catalog, and "Validate the app configuration" before you click Deploy. Fixing a mistake after deploying costs another 5-8 minutes.
6. The deployment takes 5-8 minutes and the web page may look broken for a minute or two after that. Refresh before you assume it failed.
7. The checker lags. If a check fails right after a step, wait 30-60 seconds and click again.
8. If the template check says "Please ensure that 'Create Service Account' is unchecked for the 'frontend' component": click frontend, click Show advanced fields, uncheck Create Service Account, click Save. Then click frontend again and confirm the box stayed unchecked before you recheck. The canvas layout does not matter to the checker, only the settings and connections.

## Setup

Open Cloud Shell and paste this. It stops and asks one question: type the region from your lab page and press Enter.

```bash
cat > ~/askregion.py <<'EOF'
import os, re
while True:
    v = input("Region from the lab page: ").strip().split("=")[-1].strip().strip("'").strip('"')
    if re.fullmatch(r"[a-z]+-[a-z]+[0-9]+", v):
        break
    print("That does not look right, try again.")
open(os.path.expanduser("~/region"), "w").write(v + "\n")
print("region saved:", v)
EOF
python3 ~/askregion.py
```

You should see: region saved: and your region.

```bash
gcloud config get-value project 2>/dev/null > ~/project
cat ~/project ~/region
```

You should see two lines: your project ID and your region.

## Task 1. Set up App Design Center

1. In the top search bar type App Design Center and open it.
2. At the bottom of the left menu, set Region to your lab region.
3. Click Go to Setup.
4. Click Enable and wait a couple of minutes.

Check my progress: Initialize the App Design Center space.

## Task 2. Explore App Design Center features

```bash
gcloud design-center spaces list --project="`cat ~/project`" --location="`cat ~/region`"
```

You should see a space with displayName: default-space. If the list is empty, Task 1 setup has not finished or the region is wrong.

There is no check for this task.

## Task 3. Assemble the template

Create the template:

1. Templates > Create Template.
2. Template ID: leave app-template-1.
3. Template Name: simple-3-tier-agentic-app
4. Click Create template.

Component 1, the data MCP server (becomes cloud-run-1):

1. In Components > Services click Cloud Run (Service). Click the new cloud-run-1.
2. Service Name: data-mcp-server
3. Click Show advanced fields.
4. Members: type allUsers and press Enter.
5. Vpc Access > Egress: PRIVATE_RANGES_ONLY.
6. Uncheck Enable Prometheus Sidecar.
7. Save.

Component 2, the agent backend (becomes cloud-run-2):

1. Click Cloud Run (Service) again. Click the new cloud-run-2.
2. Service Name: agent-backend
3. Click Show advanced fields.
4. Keep Create Service Account checked.
5. Service Account Project Roles: add these five, one at a time, pressing Enter after each.

```text
roles/monitoring.metricWriter
roles/logging.logWriter
roles/cloudtrace.agent
roles/telemetry.writer
roles/serviceusage.serviceUsageConsumer
```

6. Members: type allUsers and press Enter.
7. Vpc Access > Egress: PRIVATE_RANGES_ONLY.
8. Uncheck Enable Prometheus Sidecar.
9. Save.
10. Drag a connection from a blue dot on agent-backend to data-mcp-server.

Component 3, the frontend (becomes cloud-run-3):

1. Click Cloud Run (Service) again. Click the new cloud-run-3.
2. Service Name: frontend
3. Click Show advanced fields.
4. Uncheck Create Service Account. This box is checked by default and it is the one people miss (see trap 8).
5. Ingress: INGRESS_TRAFFIC_INTERNAL_LOAD_BALANCER
6. Members: type allUsers and press Enter.
7. Uncheck Enable Prometheus Sidecar.
8. Save.
9. Drag a connection from frontend to agent-backend.

Vertex AI:

1. In Components > Services click Vertex AI.
2. Drag a connection from vertex-ai-1 to agent-backend.
3. Drag a second connection from vertex-ai-1 to data-mcp-server.

Load balancer:

1. Click Global Cloud Load Balancing (Backend). Click lb-backend-1. Name: galb-backend. Save.
2. Drag a connection from galb-backend to frontend.
3. Click Global Cloud Load Balancing (Frontend). Click lb-frontend-1. Name: galb-frontend. Save.
4. Drag a connection from galb-frontend to galb-backend.

You should now have six components and six connections:

```text
galb-frontend -> galb-backend -> frontend -> agent-backend -> data-mcp-server
vertex-ai-1 -> agent-backend
vertex-ai-1 -> data-mcp-server
```

Before you check, look at the arrowheads. The arrow from frontend must point at agent-backend, and the arrow from agent-backend must point at data-mcp-server. A green check here does not prove the directions are right (see trap 4).

Check my progress: Validate the template configuration.

STOP: do not go on until this check is green.

Share the template in the catalog:

1. Click Template details and confirm the ID is app-template-1.
2. Top left: click App Design Center, then Catalogs.
3. Click Add Templates. Next to app-template-1 click Add to catalog. Click Done.

Check my progress: Create the app template.

## Task 4. Deploy the app

Create the app:

1. Templates > app-template-1 > Configure an app > Create new application.
2. Name: cymbal-london-concierge
3. Deployment project: your lab project ID.
4. Region: your lab region.
5. Input Attributes > Environment: Development.
6. Input Attributes > Criticality: Low.
7. Click Create Application.

Paste this in Cloud Shell. It prints every value for the three containers with your own project and region filled in, so you can copy from the terminal.

```bash
cat <<EOF

FRONTEND  (Container 1)
  Container Image : us-central1-docker.pkg.dev/o11y-movie-guru/london-travel-agency/frontend:codelab-c2c6-v1
  Env Var         : API_BASE_URL = module.cloud-run-2.service_uri
  Port http1      : 80

AGENT-BACKEND  (Container 1)
  Container Image : us-central1-docker.pkg.dev/o11y-movie-guru/london-travel-agency/agent:codelab-c2c6-v1
  Env Var         : GOOGLE_CLOUD_PROJECT = `cat ~/project`
  Env Var         : GOOGLE_CLOUD_LOCATION = `cat ~/region`
  Env Var         : DATA_BACKEND_URL = module.cloud-run-1.service_uri
  Port http1      : 8000

DATA-MCP-SERVER  (Container 1)
  Container Image : us-central1-docker.pkg.dev/o11y-movie-guru/london-travel-agency/data_mcp:codelab-c2c6-v1
  Env Var         : GOOGLE_CLOUD_PROJECT = `cat ~/project`
  Env Var         : GOOGLE_CLOUD_LOCATION = `cat ~/region`
  Env Var         : DB_TYPE = sqlite
  Env Var         : EMBEDDING_MODEL = text-embedding-005
  Port http1      : 8002

EOF
```

You should see three sections with your real project ID and region in the env var lines.

For each of the three components, in the app canvas:

1. Click the component, then Containers > Container 1.
2. Replace Container Image with the value from the terminal.
3. Click Add Env Var for each env var: key on the left of the = sign, value on the right.
4. Under Ports, for http1, set Container Port to the value shown.
5. Save.

Do frontend, then agent-backend, then data-mcp-server. Count the env vars when you finish: frontend 1, agent-backend 3, data-mcp-server 4. Read each key letter by letter; a key such as API_BASE_UR (missing the last L) is enough to fail the check.

If the check below fails with a generic message, click Code at the top and read the three cloud-run modules:

1. cloud-run-3 (frontend) must contain API_BASE_URL with module.cloud-run-2.service_uri.
2. cloud-run-2 (agent-backend) must contain DATA_BACKEND_URL with module.cloud-run-1.service_uri, and must NOT contain cloud_run_3_SERVICE_ENDPOINT.
3. cloud-run-1 (data-mcp-server) must NOT contain cloud_run_2_SERVICE_ENDPOINT.

A line that must not be there means that connection was drawn backwards (trap 4).

Check my progress: Validate the app configuration.

STOP: do not click Deploy until this check is green.

Deploy:

1. Optional: click Code at the top to see the generated Terraform.
2. Top right: click Deploy.
3. Select Create a new service account, then Proceed.
4. When the list of services to enable appears, click Deploy at the bottom.
5. Wait 5-8 minutes until Deployment status and every component show a green checkmark. Link to logs shows the build if you want to watch.

Check my progress: Deploy the app services.

## Task 5. Verify the app

1. In the app details panel open the Outputs tab and copy the load balancer frontend external IP address.
2. Open a new browser tab, paste the IP address, press Enter. If the browser warns that the page is not secure, continue anyway; the lab uses a self-signed certificate.
3. If the page looks unstyled or empty, wait a minute and refresh.
4. In the chat, send this prompt and answer any follow-up questions:

```text
Create an itinerary for a 3-day trip to London.
```

You should get a structured London itinerary.

Check my progress: Verify the running app.

## Task 6. Explore App Hub and Application Monitoring

1. Back in App Design Center, in the app details panel click View app in App Hub. All the services of the app are listed as one unit.
2. Click View in observability.
3. Open the Dashboard tab: request rate, error rate, latency, saturation. The graphs may be empty for a few minutes after your first chat.

There is no check for this task.
